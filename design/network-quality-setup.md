# 网络质量使用说明

此文对应 C6 源码实现，尚未运行验收。质量管理入口 `/system/ipSettings`，VPS 资源列表也提供线路摘要和历史入口。

## 本地更新

1. 重新编译并启动后端，包含 `oci-dao`、`oci-monitor`、`oci-common` 和 `oci-server` 的本轮变更。网络 worker 随 monitor 模块资源打包；后端需要创建新 `network_quality_*` 实体表。
2. 打开质量管理，给要检测的实例安装或升级探针。已有资源探针不会自动获得网络任务能力；可以从“需要升级”入口重新安装。
3. 新建检测任务，填写自己确认可用的运营商目标、目标地区与协议，再选择执行检测的 VPS。任务启用后按间隔采样，也可以暂停并手动检测一次。
4. 查看实例的目标结果和独立历史。首次无数据是正常空态；排队回执只表示任务已入队，实际结果需等待探针报告。

## 运行条件

- 远端实例需要 root SSH 账户、systemd、Python 3.6+。ICMP 还需要系统 `ping`；缺少能力时记录“不支持”，不计算丢包。安装不会自动 apt/yum 安装依赖。
- 沿用该实例已保存的 SSH 连接信息。安装与升级会短暂重启资源探针，并增加 `vps-network-agent.service`；资源采样和网络测量分别运行。
- 探针需要能访问主站 `/api/network-quality/agent/poll` 与 `/agent/report`。可在后端设置 `oci.monitor.public-url` 为面向探针的 HTTP(S) 服务基址，例如 `https://monitor.example.com`；支持反向代理路径前缀。未设置时沿用原公网 IP 和服务端口。HTTPS 验证证书。
- 网络凭据只由认证安装生成，通过 SSH stdin 发送，远端配置仅 root 可读；匿名旧脚本下载不包含该凭据。卸载会停止和移除两项服务、撤销专用凭据。

## 结果含义

- ICMP：收到回包的往返时间；TCP：建立连接耗时；HTTP：GET 到响应头的耗时，接受 2xx/3xx，不跟随跳转。三种协议不合并统计。
- 超时、DNS 解析失败、连接拒绝、HTTP 错误、不支持与未收到报告分别保留。正常返回但延迟高的样本仍计为成功。
- 失败率按实际采样尝试数计算。未收到报告、不支持且未发出采样时不进入分母，不补零延迟。
- 最长展示近 7 天。统计使用所选窗口的全部当前版本记录；图表最多展示最近 720 点，明细显示最近 30 条，时间使用服务器记录时间。
- 保存配置（包括暂停和启用）生成新版本，当前图表重新累计。旧配置记录保留至 7 天清理；当前页面没有旧配置版本选择入口。
- 单任务最多 256 台实例、最多 64 个任务。每探针最多 4 项活动检测；修改中的旧任务最多占位至 120 秒租约到期，避免新旧版本重复发包。

## 与旧质量管理的区别

不再依赖额外的电信/联通/移动三台 VPS。结果反映“被监控 VPS 到所选目标”的网络质量，需要选定有代表性的运营商目标；不自动认定任意地址可以代表整个运营商。

旧自动换 IP 调度已经在源码中停用，保存旧配置也不会重新启用。更新后端后生效；新功能只测量和记录，不自动修改 IP 或云网络安全规则。

接口、凭据和版本约定见 [network-quality-contract.md](../tasks/network-quality-contract.md)。
